FABRICA - FIRST STEPS
=====================

From the directory that contains "processes":

1. Enter the process:

   cd processes/fabrica

2. Create the local environment file:

   Linux/macOS:
   cp .env.detail .env

   PowerShell:
   Copy-Item .env.detail .env

3. Configure the two independent Storage SAS connections in .env:

   STORAGE_ACCOUNT_SAS_URL_FABRICA_PLANES
   STORAGE_ACCOUNT_SAS_URL_FABRICA_KPIS

   The SAS token may be embedded in each container URL. If it is not, set the matching
   STORAGE_ACCOUNT_SAS_TOKEN_* variable. Do not commit or package the real .env file.

4. Create/synchronize the locked Python environment:

   uv sync --python 3.14.2 --frozen

   Do not use pip.

5. VALIDATE ONE SCHEDULED EXECUTION
-----------------------------------

   uv run --frozen ada-fabrica

   Fabrica is a run-once job. One process execution scans the active Fabrica streams once and
   exits. The platform schedule is responsible for starting the next execution.

6. PLATFORM SCHEDULE
--------------------

   config.detail.json provides the deployment reference for an execution every 2 hours.
   Copy/adapt it as config.json in the consumer repository before deployment.

NOTES
-----
- Planes and KPIs use independent named SAS connections.
- The Planes catalog preserves the validated 13 metrics from the legacy process.
- The KPI catalog is deliberately empty until KPI definitions are approved; an empty stream does not
  access Storage.
- Source discovery is restricted to the current America/Santiago day partition.
- Source file timestamps are interpreted as UTC.
- Incoming null values never erase existing dataset values.
- Producer state remains under .runtime/state/producers/fabrica.json.
